Test Case Format Guide
Function Mode when Function Name is set

The grader calls your function with the parsed JSON input and compares the return value against the expected output using smart JSON comparison.

Input Expected Output What happens
{"nums": [2,7,11], "target": 9} [0, 1] fn(nums=[2,7,11], target=9)
[[1,2,3], 3] 2 fn([1,2,3], 3)
["hello world"] "dlrow olleh" fn("hello world")
[[3,1,2]] [1, 2, 3] fn([3,1,2]) — single list arg
[5] 120 fn(5) — single value
{"head": [1,2,4], "node": [1,3,4]} [1, 1, 2, 3, 4, 4] fn(head=[1,2,4], node=[1,3,4])
Comparison rules: Return values are compared via JSON normalization. [1,2,3] matches [1, 2, 3]. Booleans: Python True matches true. Strings must be quoted in expected output: "hello".
Stdin Mode when Function Name is empty

The grader runs the script, feeds input via stdin, and compares stdout line-by-line (stripped).

Comparison rules: Exact string match after stripping leading/trailing whitespace. Multiline outputs must match line-by-line. Use textareas in the test form for multiline input/output.
